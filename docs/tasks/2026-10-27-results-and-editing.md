## Problem Statement

Looking at a query's result is where a database client earns its place. A grid that formats and lays out every row chokes on a large result. A table that shows numbers as unaligned text, NULL as an empty cell and binary as noise hides what the data means. Selecting, copying and pasting cells has to behave like a spreadsheet, including copying several separate ranges, repeating a pasted block and keeping NULL distinct from empty text. Editing data inline is where most accidents happen: without a reviewed preview, a real transaction and a key to find the row again, one careless cell edit can overwrite the wrong row. Document databases and Redis have no rows at all, so they need viewers of their own instead of a forced table.

## Solution

Results appear below the editor in Result, Messages, Output and Plan panes, with each statement's outcome, timing and notices. The Result grid virtualizes rows and columns, numbers and aligns values by type, shows NULL distinctly and renders every value class, and supports rectangular and multi-range selection, keyboard navigation, copy as TSV, CSV, JSON, SQL `INSERT` or Markdown, typed paste, paste as new rows with a column mapping preview, and whole-operation undo. Inline edits collect in a pending Changeset with their own highlight colors; Preview shows the generated DML and Apply runs it in a transaction, committing or rolling back, and never falls back to matching on all columns. The Value panel shows and edits a cell in full. Documents open as Table, Tree or JSON views, and Redis keys open in a key browser with per-type value views.

## User Stories

1. As a user running a query, I want a Result pane with the rows, so that I can read what came back.
2. As a user running a script, I want one result tab per statement and an Output pane, so that I can follow each statement.
3. As a user, I want a Messages pane with each statement's outcome, notices and timings, so that I know what the server said.
4. As a user, I want to see when a result was truncated at the row cap or cut short by another statement, so that I do not mistake a partial result for the whole.
5. As a user, I want a clear error panel with the message, hint and a jump to the failing line, so that I can fix a failed statement.
6. As an administrator, I want a visual plan with a summary, warnings, a hot path bar and operator cards, so that I can see where a query spends its time.
7. As a user, I want to keep a plan while I edit the statement and recompute it explicitly, so that I can compare.
8. As a user with a large result, I want the grid to scroll smoothly, so that a million rows remain usable.
9. As a user, I want row numbers and a pinned gutter, so that I can talk about a row and keep my place while scrolling sideways.
10. As a user, I want column widths measured from the data, so that I can read values without resizing everything.
11. As a user, I want numbers right-aligned, NULL in italic grey and every value class rendered for what it is, so that the data reads correctly.
12. As a user, I want a cell cut to one line with the full value in the Value panel, so that a long JSON document does not blow up the row.
13. As a user, I want to select a rectangle of cells, a whole row, a whole column or everything, so that I can copy what I need.
14. As a user, I want to add several separate ranges with ⌘-click and remove one, so that I can copy non-adjacent data.
15. As a user, I want spreadsheet-like keyboard navigation with Shift to extend, so that selecting is fast.
16. As a user, I want to copy as TSV, CSV, JSON, SQL `INSERT` or Markdown, so that the result fits where I paste it.
17. As a user, I want to copy a whole column's names with its values, so that the paste is self-describing.
18. As a user copying a large selection, I want to be asked first and see progress with Cancel, so that the app does not freeze.
19. As a user, I want Copy all results to rerun the read query, so that I get every row and not only the loaded page.
20. As a user, I want pasted text to fill or repeat across a selection and be validated as a whole, so that a paste either works or changes nothing.
21. As a user, I want pasted data to keep NULL, empty text, binary values and holes when it comes from sqlr, so that a round trip is faithful.
22. As a user, I want Paste as new rows with a mapping preview, so that a clipboard from another table lands in the right columns.
23. As a user, I want automatic IDs regenerated by default when pasting new rows, so that I do not duplicate keys.
24. As a user, I want to edit a cell inline, set it to NULL, add, duplicate and delete rows, so that I can fix data in place.
25. As a user, I want each kind of pending change highlighted, so that I can see what I am about to apply.
26. As a user, I want undo and redo of whole edits before Apply, so that I can change my mind safely.
27. As a user, I want to revert selected cells or whole rows without losing other changes, so that I can undo part of a change set.
28. As a user, I want to preview the exact DML before applying, so that I know what will run.
29. As a user, I want Apply to run in a transaction and roll back on any failure, so that a mistake does not leave half the edits.
30. As a user, I want Apply to join my open transaction, so that my own work and the edits stay together.
31. As a user, I want the app to refuse an edit when a row changed elsewhere, so that I never overwrite someone else's data.
32. As a user, I want a read-only result to explain why it cannot be edited, so that I know whether to open the table.
33. As a user, I want a read-only Session never to offer edits, so that the protection holds.
34. As a user, I want the table's own rows opened in a new tab when the result cannot be edited, so that I can edit there.
35. As a MongoDB user, I want Table, Tree and JSON views of my documents, so that I can scan, explore and edit them.
36. As a document user, I want a document without an `_id` to be read-only, so that no edit can hit the wrong document.
37. As a document user, I want the JSON editor to highlight and flag syntax errors, so that I can fix a document before saving.
38. As a Redis user, I want keys grouped by prefix with types and TTLs, so that a flat key space is navigable.
39. As a Redis user, I want SCAN paging with a match pattern, so that browsing never blocks the server.
40. As a Redis user, I want a value view per type with paging, TTL editing, rename and delete, so that I can work with strings, hashes, lists, sets, sorted sets and streams.
41. As a Redis user, I want a console for raw commands with history, so that I can do what the browser does not cover.
42. As a user on a read-only or production Connection, I want document and Redis edits to follow the same confirmations as SQL, so that protections are consistent.

## Implementation Decisions

- The grid is custom-painted and virtualized on rows and columns. It holds its own state (selection rectangles, sort, condition, edit buffer, history) and returns actions; it calls no engine.
- Header boundary drags resize columns with a 60-point minimum. Manual widths stay with the column set across page loads and display-format changes; resizing leaves selection and sorting unchanged.
- The typed clipboard lives in core: selected cells with their columns, pending overrides, regions and holes, encoded to text and kept next to it. Text and values stay bounded; a copy larger than a threshold goes to a background job.
- Copy formats are text encoders in core. TSV names columns only for whole columns, CSV always, JSON writes objects, SQL `INSERT` uses the edited table's name, and Markdown writes a table.
- Paste parses external text as TSV, coerces values by column kind, applies to a trial edit buffer, and commits only when every value validates. Repeated blocks tile when the rectangle is a multiple of the block, else apply once from its corner clipped at the grid's boundaries. Paste as new rows runs a mapping preview and, past 1,000 rows, a background thread.
- Edit buffers hold key columns, writable and `NOT NULL` flags, automatic and default flags and missing required columns, updates, inserted rows and deleted rows. Inserted rows are numbered far above loaded rows so their identity is stable as pages load.
- Grid edit history keeps whole edit buffers (100 operations or 32 MiB). Undo and redo swap buffers; Apply or a reload starts a new history.
- The Changeset is a core type: table, key columns and update, insert and delete changes. It merges a row's updates into one `UPDATE`, orders deletes, updates and inserts, generates DML through the Dialect with bound parameters, and renders a preview with literals.
- Applying a Changeset is an engine Job on the tab's Session. It chooses its own transaction, opens one in Manual or Smart mode, or joins an open transaction behind a savepoint; every statement must affect exactly one row.
- Editability is worked out by the app from the Result's column origins, the Driver's editable-results capability, the Session's read-only state and the table description, and is explained in the result bar.
- Document tabs hold three view states per Result. The Table view builds rows from the documents with the first page's top-level keys and a memory budget; the Tree view decodes only expanded documents; the JSON view edits one document as Mongo shell literals.
- Document edits are identified by `_id`, plus the hit's `_index` on Elasticsearch, and are applied through Jobs so the Connection profile's confirmations apply.
- The Redis browser groups keys by prefix in core-side data, pages with SCAN, keeps at most eight patterns per database, and pages a value per type with the type's scan command. Edits are typed operations (set field, push, remove, add member, TTL, rename, delete, create) executed by the Driver.
- The Plan pane is a UI widget over a plan model from core. Explain statements per engine and their parsing are Driver concerns; the pane draws a summary, warnings, a hot path bar and operator cards with an inspector, and keeps the plan until the user recomputes it.

## Testing Decisions

- Seam: the grid widget through `egui_kittest`, with simulated clicks, keys and clipboard events. Prior art: the grid interaction suite and the grid editing suite for selection, navigation, copy formats, paste, multi-range operations, undo, revert and delete marking.
- Seam: the grid's edit buffer and clipboard modules directly. Prior art: editability reasons, key handling, typed input, duplicate and default rules, paste tiling and clipping, validation refusing a whole paste, mapping preview errors and automatic ID regeneration.
- Seam: the core Changeset and clipboard model directly. Prior art: update, insert and delete DML, composite keys, key-column edits, quoting of awkward names, literal previews, malformed keys, typed clipboard holes and null versus empty text.
- Seam: the engine's apply Job and clipboard Jobs against a fake or shared database. Prior art: the apply suite (transaction modes, one-row checks, rollback, savepoint join, read-only refusal), and the clipboard suite (complete reads, read-only enforcement, progress and cancellation).
- Seam: the document views and the Redis widgets through `egui_kittest`. Prior art: the document widget suite for the table budget, tree expansion, JSON validation and the key browser grouping; the key-value widget suite for TTL parsing, value paging and typed edits.
- Seam: the app with real Redis and document services where needed. Prior art: the app's Redis and integration suites.
- Seam: display formats in core. Prior art: null text, booleans, numbers, grouping, decimals, temporal patterns, binary styles, JSON compaction and export behaviour.

## Acceptance Criteria

- [x] A single run shows Result and Messages, and a script shows one result pane per statement plus Output, Messages and Plan.
- [x] Messages list each outcome, notice and transaction note with time and level, and can be copied as text.
- [x] Result errors show the message, hint, statement, a copy action and a link to the failing line.
- [x] Truncation at the row cap is stated in Messages, and a cut-short result says so in the status bar. SQL Results spill at the memory budget while fetching continues.
- [x] The Plan pane shows a summary, warnings, a hot path bar, operator cards, an inspector, a raw toggle and a stale recompute offer.
- [x] The grid virtualizes rows and columns and paints only the viewport.
- [x] Column widths are measured once per column set from the header and the first 100 rows.
- [x] Row numbers, a pinned gutter, zebra stripes and sort marks are drawn.
- [x] NULL is italic grey, numbers right-aligned, and each value class renders by its kind and display hint.
- [x] Cells are cut to one line and 200 characters, with bytes cut at 32 bytes plus their count.
- [x] Rectangular, row, column, all-cells, Shift-extended, drag and ⌘-click multi-range selections work, and ⌘-click removes a range.
- [x] Arrow, Page, Home and End navigation works with Shift extension and keeps the column.
- [x] Copy as TSV, CSV, JSON, SQL `INSERT` and Markdown works, a single-cell copy is bare, and whole columns include headers.
- [x] A typed clipboard keeps column names, NULL versus empty text, binary values and holes.
- [x] A copy over 100,000 cells or an estimated 1 MiB asks first, runs in a background job and can be cancelled.
- [x] Copy all results reruns the read query as a cancellable job and is refused for non-reads and pending changes.
- [x] A single pasted value fills the selection; a block repeats and tiles, else applies once from each corner clipped at the edges.
- [x] Every pasted value is validated before the pending edits change, and an invalid one refuses the whole paste.
- [x] Paste as new rows offers column mapping, header handling, required-column checks, duplicate-mapping refusal and automatic ID regeneration.
- [x] A result's editability is explained in the bar, and a read-only result offers opening the table.
- [x] Inline editing, the Value panel editor, Set NULL, add, duplicate, delete and revert work with the type rules.
- [x] Edited cells, inserted rows and deleted rows are highlighted, and inserted defaults say DEFAULT.
- [x] Whole-operation undo and redo work before Apply, clear redo on a new edit and reset on Apply or reload.
- [x] Preview generates the DML with literals, and Apply runs it in its own, an opened or a joined transaction.
- [x] A statement affecting a number of rows other than one rolls back the whole Changeset with the row label.
- [x] Read-only Sessions and Drivers without editable results never get a Changeset.
- [x] Documents open as Table, Tree or JSON, and editing requires an `_id`.
- [x] The JSON view validates a document, accepts Mongo shell literals, highlights and marks its first error, and beautifies.
- [x] Redis keys are grouped by prefix with type badges and TTLs, and SCAN pages with Load more and a match pattern.
- [x] Redis value views cover strings, hashes, lists, sets, sorted sets and streams, with paging, TTL, rename, delete and typed edits.
- [x] Grid columns can be resized by dragging, with a 60-point minimum; manual widths survive page loads without changing selection or sorting.

## Out of Scope

- Cross-database joins or structural table copying.
- Fill-down and fill-right commands.
- Preserving the selection across a sort or a reload.
- Editing a Redis module value other than through the console.
- Export and import formats, which are a Data and schema tools concern.

## Further Notes

This task records retroactively the area as it exists. Columns start with measured widths and can be resized by dragging their header boundaries. The filter field is a SQL `WHERE` condition that reruns the query on the server.
