sqlr.

A universal database client: native Rust, egui, no webview. One app for relational, document and key-value databases — and any other database you add by writing a driver. Open source, MIT licensed.

Rust native + egui No webview MIT licensed 60 fps on 1M+ rows

01What it does

A complete set of database development tools in a fast native UI. The highlights:

Grid editing

Double-click a cell, add, duplicate or delete rows. Changes are tinted until you Preview the generated SQL, then Apply or Discard. Concurrent changes from other sessions are detected and named.

SQL editor for big scripts

Only visible lines are laid out: a 10 MB file scrolls and takes typing in well under a frame. Statement coloring, autocomplete, find/replace, multi-caret editing, formatting (⌥⌘L) and a command palette (⌘⇧P) over commands, snippets and history.

Profiles & commit modes

Each connection gets a Development, Test or Production profile — with its color, commit mode (Auto, Manual, Smart), a read-only flag and confirmation rules for writes and destructive statements.

Object editors

Tables, views, indexes, sequences, functions, triggers, schemas and databases open in tabs with sub-tabs for structure, definition, dependencies and sample data.

Transfer tools

Export queries to CSV/JSON, import files back, and copy between connections — including between two different database engines, row by row.

NoSQL, first class

MongoDB and Elasticsearch get document views with expandable JSON trees; Redis gets a key-value browser. A MongoDB shell subset covers the everyday commands.

04Architecture

A small set of crates with strict boundaries. The UI thread never does I/O; all database work runs on the tokio runtime off the main thread.

CrateRole
sqlr-coreDomain types, columnar chunks, driver traits. Depends on nothing internal.
sqlr-driver-*One driver per database (tokio-postgres, …).
sqlr-engineTokio runtime off the UI thread: sessions, explorer/catalog cache, results, history, installed sidecar drivers.
sqlr-sidecarSidecar protocol, SidecarDriver client, the serve loop.
sqlr-registryDriver-file installs, versions and review, no UI.
sqlr-driver-sdkWrite a driver as a sidecar: re-exports the API and run.
sqlr-driver-testsConformance suite for drivers (dev-dependency only).
sqlr-storeConnections TOML, encrypted credential vault, settings.
sqlr-uiegui widgets: grid, tree, forms, docked panels.
  • Security: no OpenSSL (rustls only); secrets live in an encrypted vault protected by the OS keychain and arrive at connect time.
  • Threads: the UI thread never does I/O; every engine call is async on tokio.
  • Caching: catalog explorer and autocomplete share one in-memory cache with bounded size.

native Rust + egui + tokio
// and deliberately not:
no webview · no Electron · no JVM

05Adding a database: sidecars

A database sqlr doesn’t ship with becomes a sidecar driver: a separate executable that sqlr starts and talks to over stdio. Frame protocol v1.0.0 — each message is one length-prefixed frame:

bytesfield
4length — big-endian u32, size of everything after it (9 + payload)
1type
8request id — big-endian u64
…payload (MessagePack for control frames)

Frames are capped at 64 MiB; a driver can be written in Rust with sqlr-driver-sdk — or in any language that can read and write the frames.

# scaffold a driver from the template
cargo generate --path templates/sqlr-driver-template --name my-driver
cd my-driver
cargo test

06Build & run

Requires Rust 1.98+ (workspace edition 2024). The default cargo commands act on the app; sidecar drivers are extra binaries.

# run the app
cargo run

# release build
cargo build --release

# test the workspace + driver conformance
cargo test

# exercise the HANA/JDBC sidecars
cargo test -p sqlr-driver-hana
